# DebtTracker: подготовка к публикации в Google Play

Статус: **черновик; публиковать ещё рано**. Этот документ — список проверок, а не подтверждение готовности.

## Код и сборка

- [ ] Сверить изменения локального проекта с веткой GitHub и объединить PR после ревью.
- [ ] Выполнить Gradle unit tests, assembleDebug и bundleRelease в Android Studio с установленным Android SDK.
- [ ] Проверить сценарии: создание/изменение/удаление долга, частичное уменьшение, полное погашение, архив, история, статистика, напоминания и восстановление после перезапуска.
- [ ] Проверить корректность на Android 9, Android 10 и современной версии Android, в обеих темах, с крупным шрифтом.
- [ ] Убедиться, что миграция Room с версии 1 на 2 сохраняет данные.
- [ ] Принять решение по пакету приложения: сейчас \`com.example.debttracker\`. После публикации смена applicationId невозможна как обновление того же приложения.
- [ ] Убедиться, что targetSdk не ниже 36 (на GitHub выставлено 37). Проверить требования поддержки новых API и работу edge-to-edge.
- [ ] Подготовить подписанный Android App Bundle (AAB), безопасно хранить ключ подписи, включить Play App Signing.
- [ ] Проверить правила резервного копирования: \`android:allowBackup="true"\`; финансовая информация может попадать в бэкапы устройства. Проверить XML backup/data extraction rules и содержание политики.
- [ ] Не менять формат Room и applicationId без плана миграции/переноса пользовательских данных.

## Play Console и данные

- [ ] Создать / настроить аккаунт разработчика и карточку приложения; подготовить иконку, скриншоты, тексты описания.
- [ ] Разместить публичную политику конфиденциальности по HTTPS, указать контакт, политику хранения/удаления и фактические потоки данных; дать доступ к политике из приложения.
- [ ] Заполнить Data safety, App access, Content rating, Target audience и остальные декларации в Play Console.
- [ ] Проверить разрешения \`POST_NOTIFICATIONS\`, \`RECEIVE_BOOT_COMPLETED\` и отсутствие ненужных разрешений.
- [ ] Проверить отсутствие сторонней телеметрии, SDK сбора данных и фактическую работу резервного копирования, прежде чем писать «не собираем данные».
- [ ] Если аккаунт *личный*, зарегистрирован после 13.11.2023 — пройти закрытое тестирование как минимум с 12 участниками, непрерывно 14 дней, а затем запросить Production access.
- [ ] Загрузить подписанный AAB в подходящий тестовый трек, проверить pre-launch report и исправить замечания.
